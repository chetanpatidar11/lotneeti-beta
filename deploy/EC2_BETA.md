# Lean EC2 beta deployment

This is the operator runbook for the single-host beta deployed on 2026-09-27; exact live resources are in `docs/FINAL_HANDOFF.md`. Use one small EC2 host for PostgreSQL, Redis, Django/Gunicorn, Celery worker/beat and Next.js behind Nginx. Keep PostgreSQL, Redis, Gunicorn and Next.js bound to loopback. Open only SSH (restricted operator source), HTTP for certificate/redirect, and HTTPS to the public network. Prefer a non-root AWS role/user for future AWS CLI actions. The founder explicitly allowed the existing root CLI session for this student-account setup; the running EC2 application uses only its scoped instance role.

## Order of operations

1. Confirm the AWS account/region and authorized identity. Create or verify an account-level monthly cost budget with an email notification, then record its name, limit, threshold and subscriber. An existing budget without a verified notification does not complete L08.
2. Deploy `deploy/aws/private-buckets.template.json` with `--capabilities CAPABILITY_IAM` and `--tags Project=LotNeeti Environment=Beta`. The stack creates encrypted private buckets, scoped S3 policies and an EC2 instance profile with only those policies. Confirm the bucket public-access blocks and policies before attaching the profile to the host.
3. Start one EC2 host in a public subnet with an encrypted root EBS volume, the stack's instance profile and resource tags. Do not add a load balancer, NAT gateway, managed database or managed Redis.
4. Prepare the host, deploy the reviewed revision, verify HTTPS and perform a real isolated backup/restore drill. Enable the nightly backup timer after the drill.

An EC2 `*.amazonaws.com` hostname cannot receive a public certificate for that name. For a temporary URL without buying a domain, use an IP-based `sslip.io` hostname such as `IP-WITH-DASHES.sslip.io` and a free Let's Encrypt certificate. Treat the hostname as temporary: a changed public IP needs a new hostname and certificate. Verify DNS resolves to the host before requesting the certificate. Create `/var/www/letsencrypt`, render `deploy/nginx/lotneeti-http.conf.template` for the hostname and start Nginx on port 80. Request the certificate with `certbot certonly --webroot -w /var/www/letsencrypt -d HOSTNAME`, then replace the bootstrap config with `deploy/nginx/lotneeti.conf.template`. Its challenge location lets Certbot renew the certificate while Nginx stays up. Install `deploy/letsencrypt/reload-nginx.sh` under `/etc/letsencrypt/renewal-hooks/deploy/` with mode 0755 so new certificates are served. Test `certbot renew --dry-run --no-random-sleep-on-renew` before inviting users.

## Prepare the host

Install Python 3.12+, PostgreSQL 17 server/client, Redis, Node.js 22, Nginx, Certbot and a TLS certificate for the beta hostname. Create an unprivileged `lotneeti` user and place the reviewed checkout at `/opt/lotneeti` owned by that user. Create `/var/lib/lotneeti` for Celery Beat and `/etc/lotneeti` for root-controlled environment files. PostgreSQL and Redis must be enabled locally before the app units start. Create the application PostgreSQL role/database with a strong external password; do not use the development Compose trust-auth setup.

Create `/etc/lotneeti/app.env` with mode 0600, readable by root/systemd. Supply all required production settings: `DJANGO_SETTINGS_MODULE=config.settings.prod`, `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `FRONTEND_BASE_URL`, `DEFAULT_FROM_EMAIL`, `EMAIL_DELIVERY=ses`, `AWS_SES_REGION=us-east-1`, PostgreSQL settings, `POSTGRES_HOST=127.0.0.1`, `POSTGRES_SSLMODE=disable` for loopback-only local PostgreSQL, `REDIS_URL`, founder-approved `PLANNER_PLATFORM_CROSS_FUNDING_POLICY=WARN`, `EXPORT_S3_BUCKET`, and `API_BASE_URL=https://BETA_HOST/api/v1`. Next.js must call the API through the HTTPS Nginx endpoint because direct loopback requests fail production host/HTTPS checks. Verify the one SES sender/recipient email identity in the same region; while SES is sandboxed, any added test recipient must also be verified. Attach the sender-scoped `ses:SendRawEmail` policy from `deploy/aws/private-buckets.template.json` to the existing EC2 role by setting the `SESSenderEmail` stack parameter. SES uses the instance profile; do not store SMTP or AWS access keys in the environment file. The host must have a private exports bucket and a private backup bucket configured before external beta use.

Install the four application unit files in `deploy/systemd/` under `/etc/systemd/system/`, reload systemd and enable them. Render `deploy/nginx/lotneeti.conf.template` by replacing `__DOMAIN__` with the actual beta hostname, install it under `/etc/nginx/sites-enabled/`, check with `nginx -t`, then reload Nginx. The certificate paths in the template must exist first. Nginx and Gunicorn access logs omit raw request URLs because login and other queries may carry private values; the Django request logger emits route patterns and status instead.

## Deploy a reviewed revision

Use `deploy/push-from-workstation.sh` from a reviewed local worktree; the exact live command is in `docs/FINAL_HANDOFF.md`. On the host, it runs `bash /opt/lotneeti/deploy/deploy.sh` as root. The script installs backend dependencies, runs `npm ci` and a production build, checks Django production configuration, applies migrations, collects static assets, restarts the four app services and verifies they are active. It does not pull or merge code. Check `https://<beta-domain>/api/v1/health/`, sign-in, a planner preview and an export download with synthetic data. If a deploy fails, inspect the four unit journals, repair the failure and rerun with a previous reviewed source tree; database migrations are not automatically reversed.

Enable the backup timer only after following `deploy/BACKUPS.md` and completing a real isolated restore drill. Configure budget alerts before leaving chargeable resources running. The 2026-09-27 live deployment, restore drill and HTTPS checks are recorded in `docs/FINAL_HANDOFF.md`.
